This 3D platformer mechanics kit is configured through the Content Browser, Details and Blueprint nodes. No code is needed.

Install the plugin

Requirements: Unreal Engine 5.3–5.8, Windows. A Blueprint-only project needs nothing else to play in the editor; packaging needs Visual Studio 2022 (see "Packaging").

  1. Add the product to your library on Fab, then in the Epic Games Launcher > Library > Fab Library press Install to Engine and pick your engine version (5.3–5.8). (To install by hand, copy the plugin folder into your project's Plugins folder.)
  2. Open your project. If Unreal asks to enable the plugin or rebuild, accept. Otherwise open Edit > Plugins, search for PlatformerKit, tick Enabled and Restart Now. The plugin enables the engine plugins it needs (Enhanced Input, ACL, Control Rig, RigVM, Full Body IK, Animation Data).
  3. In the Content Browser open Settings and tick Plugin Content (5.3–5.5: Show Plugin Content). The kit's assets are in the plugin folder Proving Grounds: 3D Platformer Mechanics (folder PlatformerKit).
  4. Open Proving Grounds: 3D Platformer Mechanics > Maps > Corridor_Menu and press Play. Every map sets its own game mode, so you do not change Maps & Modes, and the demo does not touch your project's game mode or input settings. Pick a level with the mouse or the gamepad stick; all of them are open.
  5. Optional: set Project Settings > Maps & Modes > Game Default Map to Corridor_Menu so a packaged game starts at the menu.

Put your own assets in your own Content folder, never inside the plugin folder, so updating the plugin never overwrites your work.

Project render settings

The demo maps are lit for Lumen. A project made from the UE 5.5–5.8 Third Person, Blank or another template at the default Maximum quality already has all of these (a 5.3 or 5.4 template project has all but Allow Static Lighting: set it Off). A project upgraded from UE4, or made with the Scalable preset, may not. Check Project Settings > Engine > Rendering:

Setting Value Needs editor restart
Global Illumination > Dynamic Global Illumination Method Lumen no
Reflections > Reflection Method Lumen no
Shadows > Shadow Map Method Virtual Shadow Maps yes
Software Ray Tracing > Generate Mesh Distance Fields On yes
Default Settings > Allow Static Lighting Off yes

Without them the maps still load and play with no errors, but Unreal then lights them without Lumen (no dynamic global illumination, screen-space reflections), so the look differs from the listing images. Nothing else is needed: no input mappings, no collision channels or profiles, no console variables.

Find the controls

Open Proving Grounds: 3D Platformer Mechanics > Blueprints. Select a placed gameplay actor and press Ctrl+B to locate its Blueprint. Put one Core/BP_Control in each level. Its numbered Details categories control difficulty, camera, theme, HUD and testing.

All menu entries are open: Course 1 to 4, Boss 1, Boss 2 and the System Gallery. Use System Gallery to inspect every mechanic, the courses to play them in context, and the two boss maps for the fights.

Replace the hero's mesh and animation set

Stop Play before editing the assets. The gameplay character remains BP_Character; the steps below change its appearance and clips. They do not turn an arbitrary Pawn or an unrelated Third Person Blueprint into the template's gameplay character; for that, see Integrate with your own character below.

  1. Duplicate the theme you want to customize into your own Content folder. Keep the original as a reset point.
  2. Open the duplicate's Hero > Anim Set. If populated, duplicate that Anim Set too. If empty, create Add > Miscellaneous > Data Asset > CorridorAnimSet. Both Workshop themes use Characters/HeroActions/DA_HeroActions. Duplicate this set to keep its existing slide, rail, wall, rope and vehicle clips while editing your variant.
  3. In the new Anim Set, assign Mesh > Mesh. Use animation clips authored for that mesh's skeleton, or retarget your own appropriately licensed clips to it.
  4. Fill Ground > Idle, Walk, Run and Air > Jump Start, Fall Loop, plus Ground > Land. Idle is required to avoid a reference pose. Optional action slots can be filled later; a locomotion sample is not a complete action-animation set.
  5. Set Mesh Scale and Mesh Yaw so the mesh fits the existing capsule and faces the movement direction. Keep the collision capsule at radius 35 cm and half height 90 cm for the default movement tuning.
  6. Assign the new Anim Set to the duplicate theme. Select that theme on the level's BP_Control > 3 Theme. Leave the BP_Character Anim Set override empty if the theme should select it.
  7. Start Play. Check idle, movement, a double jump, spin, checkpoint death/respawn and completion. Verify the replacement remains visible after respawn.

The local rehearsal uses the existing SKM_Quinn_Simple mesh with SK_Mannequin, Mesh Scale 1 and Mesh Yaw -90. Its six existing Epic clips are MM_Idle, MF_Unarmed_Walk_Fwd, MF_Unarmed_Jog_Fwd, MM_Jump, MM_Fall_Loop and MM_Land. No new animation or retarget is required for this compatible-skeleton example. A different skeleton still needs its own compatible clip set; arbitrary skeletons and human setup time have not been verified.

Integrate with your own character

Three ways to give a character you already have the kit's gameplay. Each was measured in actual Play on Unreal Engine 5.7 (tables at the end of this section). Rows marked same code path use the same component calls as a measured row but were not played one by one.

Option Your character keeps The kit adds
A - add the Corridor Hero component (any Character) movement, jump height, animation, camera, input crates, enemy stomp / touch, checkpoints, death and respawn, kill volumes, hazards, pickups, triggers
B - reparent to CorridorCharacter (standard Character Movement Component) mesh, Anim Blueprint, camera and input (External modes) Option A + the kit's jump, double jump, spin, slide, slam and grind rails
C - ALS-Refactored character (C++) ALS locomotion, animation, camera, input, mantling, rolling Option A + double jump, spin, slide, slam and grind rails

Option A - keep your character exactly as it is

  1. Open your character Blueprint > Components > Add > type Corridor Hero > select it. Compile, Save.
  2. Play. Crates break when you land on them (and bounce you), enemies are stomped from above and kill you from the side, checkpoints are kept, and a death respawns you at the last checkpoint. Tune it in the component's Details: 1. Bounce (Crate Bounce Velocity 771 cm/s, Held Bounce Scale 1.25) · 2. Attack (Attack Radius 110 cm) · 3. Death (Respawn Delay 0.8 s, Immortal).
  3. Attacks: from your attack input (or an attack montage notify) call Start Attack on the Corridor Hero component (Duration 0.3 s by default); crates and enemies inside Attack Radius break / fall. Or implement the Corridor Hero interface (Class Settings > Interfaces > Add > Corridor Hero) and return true from Is Hero Attacking while your own attack runs.
  4. Optional interface events: On Hero Bounce (return true if you launch the character yourself), On Hero Hit (return true to use your own health instead of the kit's death), On Hero Respawned. Component events: On Died, On Respawned.

Your movement, jump height, animation, camera and input stay yours. Double jump, spin, slide and slam work on Option A through the component's Move Jump, Move Spin and Move Slide nodes. Grind rails, wall runs and ropes need the kit's movement solver: on a stock Character Movement they are scenery you pass under or walk on (Option B or C give them to you). Powers, mounts, glide and the shield are Option B only. Which one to pick: Option A, B or C; per-mechanic support: Mechanics at a glance. The component keeps the checkpoint itself, so it also works with your own game mode; with the kit's BP_GameMode a death is counted in the HUD and medals like the kit hero's.

Option B - the kit's moves on your character

For characters on the standard Character Movement Component, such as the Third Person template character. 1. Your character Blueprint > Class Settings > Details > Class Options > Parent Class > CorridorCharacter. Compile. Your CameraBoom / FollowCamera keep their names (the kit's own are CorridorCameraBoom / CorridorCamera). 2. Class Defaults > Details > Corridor > Integration: - Animation Mode = External: your mesh and Anim Blueprint stay. The kit's spin, slide, double jump and slam clips play as montages on Action Slot (default DefaultSlot); your Anim Blueprint needs a Slot 'DefaultSlot' node before Output Pose (the Third Person ABP_Unarmed has one). Your locomotion comes back when the action ends. The clips are on the UE5 Mannequin skeleton: a UE5 Mannequin-based character plays them with no extra step (measured on 5.7: no Compatible Skeletons entry needed; on 5.3–5.6, if a clip does not play, add the kit skeleton to your skeleton's Compatible Skeletons). A character with different bone names needs the clips retargeted (IK Retargeter) into a copy of DA_HeroActions, set as Anim Set (Details > Corridor | Animation). - Input Mode = External: the kit adds no input of its own. Your existing Jump / Stop Jumping nodes now run the kit's jump, held jump and double jump. Bind your own keys to On Spin Pressed / Released, On Slide Pressed / Released (slide on the ground with the stick pushed, crouch without it, slam in the air) and On Power Pressed. With Input Mode = Own instead, the kit's input is added at Corridor Input Priority 1, above your contexts (0), so a key both map (Space, arrows) does only the kit's action. - Camera Mode = External: your camera stays active; the kit's camera and camera director switch off. 3. Movement feel: the kit sets walk speed, jump velocity and gravity at Play. Everything else on your Character Movement stays yours; the Third Person template keeps Air Control 0.35, Max Acceleration 1500, Braking Deceleration Walking 2000 / Falling 1500, Rotation Rate 500 and Use Separate Braking Friction on. For the kit's exact air steering and stops (the demo levels are tuned on them), click the reset arrow on those fields in the Character Movement Details (kit: 0.9, 3214, 0 / 5266, 720, off). 4. Slide, triple-spin and Cyclone speeds are kept as a multiple of your walk speed, even if your character rewrites Max Walk Speed every frame.

Option C - ALS-Refactored

Two sample classes ship as source text in Documentation/Integration/ALS/ (not a module of the kit; ALS-Refactored is not part of the kit). Tested with ALS-Refactored tag ue-5.7 (commit 3268c12a20, MIT licence) on Unreal Engine 5.7. 1. Copy AlsCorridorMovementComponent.h, AlsCorridorCharacter.h and AlsCorridorCharacter.cpp into your game module's source folder. 2. In your module's .Build.cs, add "ALS", "ALSExtras", "EnhancedInput" and the kit's module "PlatformerKit" to PublicDependencyModuleNames. 3. ALS's example character has no initializer constructor, so a subclass cannot swap its movement component. In Plugins/ALS/Source/ALSExtras change two lines: header AAlsCharacterExample(); -> explicit AAlsCharacterExample(const FObjectInitializer& ObjectInitializer = FObjectInitializer::Get());; cpp AAlsCharacterExample::AAlsCharacterExample() -> AAlsCharacterExample::AAlsCharacterExample(const FObjectInitializer& ObjectInitializer) : Super{ObjectInitializer}. If your own class derives from AAlsCharacter directly, change the sample's base class to yours instead; no ALS edit is needed then. 4. Build. Open your ALS character Blueprint (for example B_Als_Character) > Class Settings > Parent Class = Als Corridor Character > Compile > Save. Its Character Movement is now AlsCorridorMovementComponent; mesh, Anim Blueprint (AB_Als), settings and camera stay as they were. 5. Details > Corridor Hero > 4. Moves: heights and speeds (defaults = the kit hero's: double jump +211 cm, slide x1.6, slam 1286 cm/s, 36 cm hop). Corridor > Spin Action / Slide Action: your two Input Actions (add their keys to your Input Mapping Context). Jump stays ALS's Jump action: on the ground ALS jumps, in the air it is the kit's double jump, on a rail it hops. 6. Optional: Spin / Slide / Double Jump / Slam Clip play on Action Slot of your Anim Blueprint (the kit's clips are on the UE5 Mannequin skeleton; ALS uses its own SK_Als, so retarget first). Blueprint getters for your Anim Blueprint: Is Sliding, Is Slamming, Get Hero Traversal (Grind / WallRun / Rope). 7. Movement feel: AlsCorridorMovementComponent Rise / Fall Gravity Scale = 1 keeps ALS's own jump arc; 3.3 / 1.08 is the kit hero's gravity shaping. With ALS's 375 cm/s walk, the kit's demo gaps are tuned for a faster hero, so judge the values in your own levels.

ALS mantles onto crates (its own feature); a crate that breaks under a mantle makes ALS ragdoll (ALS setting Mantling > Start Ragdolling On Target Primitive Destruction). The sample blocks ALS mantling during the slam and turns the slam's 1286 cm/s landing into a normal ALS landing (ALS would ragdoll above 1000 cm/s). Wall runs and ropes take the same code path as the grind rail but were not played on ALS. ALS has no grind or slide pose of its own; map Get Hero Traversal / Is Sliding in its Anim Blueprint.

Build curvy grind rails

Place BP_GrindRail and edit its Path spline like any spline: add points for S-bends, raise or lower them for climbs and drops. The hero rides every bend at Speed, leans into it (Curve Lean Radius, the Anim Set's Rail Lean Left / Right clips) and banks (Curve Bank Angle, 0 = upright). Two read-only values under Corridor > Rail show what your line asks for: Tightest Curve Radius and Peak Turn Rate. Keep the radius at or above Speed / 150 deg/s (393 cm at the default 1029 cm/s); tighter bends still ride, but the camera turns no faster than its Max Turn Rate there.

While grinding, the camera follows the rail: it rides behind and above the hero and turns into a bend before the hero reaches it. Tune it for every rail on the hero's Camera Director > Rail Camera (follow distance, height, look ahead, slope follow, turn smoothing, max turn rate, blend time), or for one rail with Override Camera + Camera Settings on that rail. Rail Camera off on a rail keeps the level camera there.

To put an obstacle on a bend, set the BP_RailObstacle's On Rail to the rail and Rail Distance to the spot: it sits on the line and turns with it. A jump between rails works on bends too: push the stick toward the other rail and press Jump, or end one rail over a gap so its launch lands on the next one. Course 4's rail section shows each of these.

Adjust the Workshop pickup presentation

Open your duplicate Workshop theme. Orb Visual Scale changes the displayed Orb and its flight to the HUD. Pickup Guide Distance sets the recognition range in centimetres. The supplied values are 2.0 and 700. Set the distance to zero to hide the contextual card and marker. In Workshop Run, approach an intact crate and check its symbol, name and action in the HUD.

In the theme's effect map, choose an event such as Loot, Slam or ShieldLose to replace its effects. The supplied effects are under Art/Feedback/Effects. Preserve the existing debris entries when customizing CrateBreak. The EnemyImpact event plays where a launched enemy hits its first neighbor.

For shared UI colors and font faces, duplicate the UI style data asset under Themes (the one the demo menu uses) and assign your style on the level’s BP_Control under HUD. Open the level menu and play a route to check both menu and HUD text.

Change settings during Play

From a Level Blueprint or your own gameplay Blueprint, get the level's BP_Control, set the relevant properties, then call its Apply node.

Change Expected behavior
Camera Distance, Camera Pitch, Field of View Updates the default camera. A placed camera view can still supply its own framing.
Counters, Hide After, Show Orbs / Crates / Lives Updates the HUD settings.
Rule, Start Lives, Max Lives A rule or life-limit change during Play starts a fresh life count.
Camera or HUD only Preserves the current life count.
Theme / hero Anim Set Configure before Play and restart Play so the already-spawned actors initialize from it.

Keep Immortal off when checking damage and respawn. Keep all demo entries open; unlock rules are an optional feature for the game you build.

Saved Blueprint examples

The three actors in Blueprints > Examples demonstrate runtime changes through the existing control. Place one BP_Control and the example actor in your level. Select the example and edit 1 Example Settings in Details. The examples do nothing automatically; call Apply Example during Play when your game needs the change.

Each saved function gets the level control, checks that it exists, sets only its own group of properties, then calls Apply. If no control exists it returns safely. The graphs use ordinary Blueprint and native project functions; no authoring plugin, Python or console command is needed.

Example actor Editable defaults Effect
BP_CameraExample Distance 880 cm, pitch -24 degrees, FOV 84 degrees Changes the default camera; preserves remaining lives. A camera-view actor can still override framing.
BP_HudExample Auto Hide, 3 seconds, orbs hidden, crates/lives shown Changes counter settings; preserves remaining lives.
BP_RuleExample Classic, 6 starting lives, maximum 9 Changed rule/life limits reset lives to the starting count, capped by the maximum. Reapplying unchanged values preserves remaining lives.

Three Level Blueprint recipes:

  1. Camera on an event: place BP_CameraExample, open the Level Blueprint, drag that actor from the World Outliner into the graph, drag from its reference and choose Apply Example. Connect your event's execution pin to the call. For an initial preview, use Event BeginPlay followed by Delay 0.1 seconds so the control and hero have initialized.
  2. HUD on a trigger: place BP_HudExample and a Trigger Box. Select the trigger, open the Level Blueprint and add its Begin Overlap event. Compare Other Actor with Get Player Pawn using Equal (Object) and Branch. Connect True to Apply Example on the placed HUD example reference.
  3. Rules at a checkpoint: place BP_RuleExample, configure its life limits, then call Apply Example from your checkpoint activation event using its actor reference. A changed limit resets lives immediately, so use this deliberately. Calling it again with the same rule and limits does not refill lives.

Open an example's Apply Example function to inspect or copy the underlying Get / Is Valid / Set / Apply chain. The internal QA_BlueprintExamples fixture contains three saved Level Blueprint calling functions and a separate save slot; it is excluded from delivery copies. The three example actors themselves are included.

Packaging

  1. Add the maps you ship to Project Settings > Packaging > List of maps to include in a packaged build. The plugin already adds its Audio, Crates, Corridor and Themes folders to the cook list.
  2. Package as usual: Platforms > Windows > Package Project.
  3. Blueprint-only projects: a Blueprint-only project has no code of its own, so Unreal builds a temporary code target for the plugin during packaging. The first package takes a few minutes longer and needs Visual Studio 2022 with the "Game development with C++" workload installed.
  4. If the packaged game logs Plugin '<name>' failed to load because module '<name>' could not be found, the plugin was copied by hand into your project's own Plugins folder and its .uplugin file lacks "EnabledByDefault": false. Add that line, or install through Fab / the launcher (which puts the plugin in the engine's Marketplace folder), and package again.
  5. After packaging, run the game and check the menu, one course, one boss start, a death and the level end screen.

Troubleshooting

  • Wrong hero: check the level's Theme, the theme's Anim Set and a direct Anim Set override on the character. A developer command-line override can also take precedence.
  • Reference pose: confirm Idle exists and the clips use the mesh's skeleton. An empty or incompatible set cannot provide a valid pose.
  • Mesh faces sideways or has the wrong size: adjust Mesh Yaw / Mesh Scale in the Anim Set first.
  • Camera does not match BP_Control: check whether a camera-view actor is active.
  • Changing the camera restores lives: verify that Rule, Start Lives and Max Lives were not also changed before Apply.
  • The package does not start or a module is missing: see "Packaging" above.
  • The demos look flat or dark: check "Project render settings" above.
  • Glide falls normally: activate the equipped Glide power and keep Jump held while descending.
